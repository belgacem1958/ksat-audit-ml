# User guide

## The paper in one paragraph

The paper audits machine-learning models that predict the saturated hydraulic
conductivity `ksat` of a soil from its retention parameters (air-entry value
`af`, Fredlund-Xing exponents `nf`, `mf`) and its void ratio `e`. The audit
table is built from the commercial SVSoils database. The central question is
the **source effect**: soils are grouped by their source (publication /
database), and a model trained on one set of sources may fail on a new source
even though it performs well in-sample.

Two generalisation scenarios are distinguished:

* **Scenario A — new source.** The source of the soil to predict is absent
  from training. Evaluated with `GroupKFold(5)` on the source label.
* **Scenario B — known source, new soil.** The source is represented in
  training. Evaluated with an intra-source 5-fold split: each source is split
  into 5 folds so that every fold contains soils from *all* represented
  sources.

Two floors are reported everywhere:

* **Global floor** — RMSE of predicting every soil by the global mean.
* **Group floor** — RMSE of predicting every soil by the mean of its own
  source. An oracle in scenario A, a legitimate reference in scenario B.

## The synthetic dataset

The commercial SVSoils table cannot be redistributed. `dataset_v2.csv` is
therefore generated by `src/synthetic/generate_synthetic_dataset.py` with the
same column schema and the same structural properties:

1. **Material signal.** `log10 ksat = signal(z1,z2,z3,z4) + interaction +
   offset + noise`, where `z1..z4` are the standardized features. The signal
   is dominated by interaction terms, so a random forest captures most of it
   (R² ≈ 0.79) while a linear model captures almost nothing (R² ≈ 0.01).
2. **Source signature.** Each source carries a *correlation* between
   `log(af)` and `log(e)` (per-source ρ, standardized to σ = 1.3, clipped to
   ±0.95). The sources share the same feature means, so a linear model cannot
   separate them and the offset stays unpredictable; a random forest detects
   the source from the joint distribution and cannot transfer its material
   signal to an unseen source.
3. **Source offset.** Drawn after the features and orthogonalized against the
   per-source feature means (least squares), so the offset is
   material-unpredictable (R² ≈ 0.02). σ = 0.3 log10 units.
4. **Source interaction.** A per-source slope on `z1`, orthogonalized the same
   way (σ = 1.2). This is what makes the grouped CV reach the global floor
   while the intra-source RMSE stays below the naive RMSE.

The generator prints the four structural diagnostics (source R², material
linear R², material RF R², offset R²) and they should match the paper's
values. See `README.md` for the exact numbers.

## The analyses

Each script in `src/analysis/` reproduces one paper result and prints the
corresponding table:

| Script | Paper result |
|---|---|
| `variance_decomposition.py` | source effect, material ~ source, hierarchical model, scenarios A/B |
| `ml_compare.py` | model comparison under naive / grouped / intra-source protocols |
| `conformal.py` | split-conformal coverage, scenarios A/B |
| `bootstrap_ci.py` | source bootstrap of the naive-vs-grouped gap |
| `feature_importance.py` | permutation importance on invisible-source folds |
| `tuning.py` | hyperparameter tuning does not beat the group floor |
| `rosetta_benchmark.py` | comparison with ROSETTA3 |
| `transfer_matrix.py` | cross-base transfer matrix (SVSoils/UNSODA/NCHRP) |
| `external_validation.py` | UNSODA/NCHRP validation, inverse transfer |

## Data provenance

* `data/synthetic/` — generated (see above).
* `data/public/unsoda_validation.csv` — UNSODA (Unsaturated Soil Hydraulic
  Database), public. 248 soils with measured ksat and retention parameters.
* `data/public/nchrp_validation.csv` and `data/public/nchrp_export/` — NCHRP
  Report 1383 database, public. 47 soils. The `nchrp_export/` folder holds the
  raw export tables; `nchrp_validation.csv` is the cleaned join used by the
  pipeline.
